你的知识库本质上覆盖的是 Tesla Model Y 的使用说明、故障处理、维护操作、服务网点和质保政策。IntentRouter 不应只匹配“车辆、空调、轮胎”等实体词，否则大量车控指令也会误触发 RAG；应同时判断用户是在查询知识，还是在要求立即执行操作。

一、知识检索 Tool 的推荐描述

可直接作为 Tool 描述：

查询 Tesla Model Y 相关的车辆功能说明、使用方法、设置步骤、故障排查、警告提示、维护保养、DIY 操作、服务中心地址与联系方式，以及车辆质保、三包和维修保障政策。适用于用户询问“怎么使用、如何设置、为什么出现、是否正常、应该怎么办、在哪里维修、是否属于质保”等问题。不负责直接控制车辆、查询车辆实时状态或执行导航。

更精简的版本：

检索 Tesla Model Y 车主手册、DIY 维护指南、服务中心信息和车辆质保政策，用于回答车辆使用、设置、故障、维护、维修网点和质保相关问题。

四、必须排除的车控指令

以下表达即使包含“空调、车窗、车灯”等词，也不应进入 RAG，而应路由到车辆控制 Tool：

打开空调
把温度调到 24 度
关闭车窗
打开后备箱
开启座椅加热
打开车灯
播放音乐
导航到公司
把音量调低

区别可以概括为：

“帮我打开空调”：执行车辆控制，不检索。
“空调怎么设置自动模式”：查询操作方法，检索。
“打开哨兵模式”：车辆控制。
“哨兵模式有什么作用”：车辆知识，检索。
“导航到最近的服务中心”：需要知识检索获取网点，再调用导航。
“服务中心在哪里”：知识检索。
五、推荐的规则判断方式

不要使用“命中任意关键词就触发”的方式。建议计算三类信号：

正向信号
命中知识实体：轮胎、充电、哨兵模式
命中查询表达：怎么、为什么、是否、什么意思
命中文档专属词：质保、服务中心、DIY、故障警报
负向信号
命中直接控制动词：打开、关闭、调高、调低、播放、暂停
句子是明确祈使指令：帮我……、给我……、把……
查询的是实时车辆状态：现在多少电、车门关了吗、胎压是多少

可以采用类似以下判断：

知识实体 + 查询表达              → 启用 RAG
文档专属高置信度词               → 启用 RAG
故障现象 + “怎么办/为什么”       → 启用 RAG
车辆实体 + 直接控制动作           → 不启用 RAG
实时状态查询                     → 不启用 RAG

最终建议把这个 Tool 的一级分类命名为：

Tesla 车辆知识与售后查询

它下面实际覆盖五种子意图：

VEHICLE_USAGE          车辆功能与使用说明
TROUBLESHOOTING        故障提示与问题排查
DIY_MAINTENANCE        DIY 维护和部件操作
SERVICE_CENTER_QUERY   服务中心查询
WARRANTY_QUERY         质保与三包政策

这样比建立一份巨大的平铺关键词表更稳定，也方便后续统计每一类知识请求的路由准确率。
